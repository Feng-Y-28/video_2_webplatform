# Claims and sources

A viral explainer is not evidence that its facts are right. Every fact on
screen must be traceable.

## Rules

1. One line per on-screen number or fact in `brief.md` → `## Claims + sources`.
2. Prefer primary sources: datasheets, user guides, the paper itself, official
   docs. A blog or reprint is acceptable only when the original is
   unavailable — say so.
3. A **simplified example** is fine and often better than a real product
   (round numbers, one port, one array). Label it as such in the brief *and*
   in the post copy. Say which direction the simplification goes
   ("we count one operation per cycle; the real unit can do two — conservative").
4. Numbers derived on screen (ratios, utilisation, peaks) must be computable
   from the listed inputs. Write the derivation in the brief.
5. A claim you cannot source is removed, not softened.
6. AI-assisted search is for *finding* sources. Open and read the source
   before you cite it.

## Line format

```
- <claim as shown> — <source title> <URL>
- <claim> — simplified example: <what was simplified and which way>
- <claim computed from the lines above> — derived
```
